# 设备信息上报 · 后端参考 API 文档（草案，未接入）

> 状态：**参考文档**。本页面为纯前端零上传实现（见 `design/rules.md` §7「零上传」），
> 本文档仅描述「若未来需要服务端接收设备信息」时的接口约定，当前**未实现、未调用**。
> 页面的「复制报告 / 导出 JSON」完全在浏览器本地完成，不发起任何网络请求。

## 1. 定位

| 项目 | 内容 |
| --- | --- |
| 目的 | 为后续「设备信息回传」预留统一的上报接口契约 |
| 当前状态 | 未接入，页面不调用 |
| 数据方向 | 客户端 → 服务端（单向） |
| 数据性质 | 匿名兼容性/环境快照，不含个人身份信息 |

## 2. 接口总览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/device-report` | 上报单条设备信息快照 |

| Header | 值 | 说明 |
| --- | --- | --- |

### 3.3 字段约定

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `reportId` | string | 是 | 客户端生成的 UUID，用于幂等去重 |
| `generatedAt` | string | 是 | `YYYY-MM-DD HH:mm:ss` |
| `pageUrl` | string | 否 | 触发上报的页面地址 |
| `collectMethod` | string | 否 | 采集方式说明 |
| `groups` | object | 是 | 7 个信息卡片的分组键值对，值均为字符串 |

## 4. 响应

### 4.1 成功

```http
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
```

```json
{ "code": 0, "message": "ok", "data": { "reportId": "uuid" } }
```

### 4.2 失败

| code | HTTP 状态 | 含义 |
| --- | --- | --- |
| `0` | 200 | 成功 |
| `40001` | 400 | 请求体不合法 / 缺少必填字段 |
| `40002` | 409 | `reportId` 重复（幂等，视为成功） |
| `50000` | 500 | 服务端内部错误 |

## 5. 安全与隐私建议（若未来接入）

1. **匿名化**：仅接收环境快照，不落 `IP`、不绑定账号、不存储 `User-Agent` 之外的指纹。
2. **限流**：按来源做令牌桶限流，防止批量伪造上报。
3. **校验**：对字符串长度与枚举范围做白名单校验，防止超长/畸形数据。
4. **保留策略**：数据仅用于兼容性统计，保留期不超过 90 天，可随时删除。
5. **合规**：接入前需在页面明确告知用户并获得同意（与 `design/rules.md` §7.5 可核对性一致）。
